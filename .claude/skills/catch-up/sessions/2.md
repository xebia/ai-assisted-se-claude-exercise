# Session 2 — target state

At the end of exercise 2, every test in the project passes and the work is
committed. Sessions 3 to 8 build on this state. The participant fixed some
of it with their own prompts; you finish the rest.

## Items, in this order

1. **Pagination, page 0 and negative pages.** `paginate()` (or the
   language's equivalent) returns a negative offset for `page <= 0`. The
   participant was asked to decide what page 0 does: page 1 again, or an
   error. **Look for their decision first**: a test case they added in the
   pagination test file, or a check already in the function. If you find
   one, satisfy it. If there is none, take the default: **page 0 and
   negative pages behave as page 1** (offset 0). Add two cases in the
   pagination test file, in the style of the existing cases: one for page
   0, one for a negative page. Then fix the function.
   Report the decision in exactly these words when you used the default:
   *"Page 0 now behaves as page 1. That was the default; session 6 asks
   for this decision, so write it down."*
2. **Create review for a book that does not exist.** The handler must
   answer 404 before it stores anything. The failing test names the
   expected status. Check book existence in the handler, following the
   pattern the book handler already uses for lookups.
3. **Review input validation.** Rating 1–5, review text 10–500 characters,
   answered with 400 before the store is called. The validation tests
   name the cases.
4. **Book create and delete status codes.** The create handler answers
   201, the delete handler answers 204 with no body. Two tests name them.

Items 2–4 may already be fixed by the participant's session 2 prompts.
Skip anything that is already green.
