# Session 1 — target state

At the end of exercise 1, every test in the project passes and the work is
committed. One test is skipped on purpose (see *Not in scope*). Later
sessions build on this state. The participant did most of it with their own
prompts; you finish the rest.

## Items, in this order

1. **Review input validation.** Rating 1–5, review text 10–500 characters,
   answered with 400 before the store is called. Session 1 task 3 adds it as
   a separate validation function (`validateReview()` or the language's
   equivalent) that the create-review handler calls. **Look for it first**:
   if the function exists, keep it and make it satisfy the tests. If there is
   none, add it that way. The validation tests name the cases.

Skip anything that is already green.

## Not in scope

- The skipped test for a review on a book that does not exist. It is a
  known bug, kept on purpose: session 1 asks Claude to find it. Do not fix
  the bug, do not unskip the test.
- The participant's own files from session 1 (a validation test file they
  asked for, notes). Do not edit or delete them.

## A red test that is acceptable

None. All tests pass (one skipped), or the report names the ones that do not.
