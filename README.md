# Claude Code Mastery — Exercises

This repository holds the starter projects used in the **Claude Code Mastery
Training**. Each project is a small **BookStore API** that manages books,
authors, and reviews.

## Participants: clone one branch

The same BookStore API is implemented in four languages. Pick the one you are
most comfortable with and clone its branch into a folder named `bookstore`:

```bash
git clone -b go https://github.com/xebia/ai-assisted-se-claude-exercise bookstore   # Go, standard library net/http
git clone -b kt https://github.com/xebia/ai-assisted-se-claude-exercise bookstore   # Kotlin / JVM, com.sun.net.httpserver + JDBC
git clone -b py https://github.com/xebia/ai-assisted-se-claude-exercise bookstore   # Python
git clone -b ts https://github.com/xebia/ai-assisted-se-claude-exercise bookstore   # TypeScript, runs on Bun
```

That folder is everything you need for the whole course: the API, the eight
exercise sheets as PDFs in `exercises/`, `preparation.pdf` (what to install
before the session; read it first), the coach skills, the frontend for
exercises 6 and 7 in `web/`, the MCP server for exercise 5 in `mcp-sqlite/`,
and the finished plugin in `bookstore-plugin/`.

Did the trainer fix a sheet on the morning of the training? `git pull` in that
folder brings it in.

## Deliberate bugs

> [!IMPORTANT]
> **These projects contain intentional bugs, smells, and questionable design
> choices.** That is the point. The exercises are designed to give you realistic
> code to investigate, refactor, and fix with the help of Claude Code.

Do not assume any piece of code is correct just because it compiles or because
its tests pass. Part of the training is learning how to use AI assistance to
spot the issues that humans (and test suites) miss.

## Trainers: `main` is the source, the language branches are build output

Edit only `main`. The `go`, `kt`, `py` and `ts` branches are generated by
`.github/workflows/package.yml` on every push to `main`: one flat package per
language, with the sheets rendered to PDF. Never edit those branches by hand
and never open a pull request against them; the next run replaces their
content. `conventions.md` explains the source layout, the package layout and
how to test a sheet.

- `bookstore-go`, `bookstore-kt`, `bookstore-py`, `bookstore-ts` — the four
  ports; `bookstore-go` is the reference version for exercise text
- `.claude/skills/` — the coach, verifier and helper skills, shipped in every package
- `bookstore-web/` — the frontend project, shipped as `web/`
- `mcp-sqlite/` — the MCP server for exercise 5: one Python file, standard
  library only, started with `uv run --script`. Read-only: two tools,
  `get_table_definitions` and `execute_query`
- `bookstore-plugin/` — everything from exercises 4 and 5 as one Claude Code
  plugin, shown live in session 5 and available to participants as a bonus
- `scripts/` and `justfile` — `just package py` builds `dist/bookstore-py`,
  the same package CI publishes
